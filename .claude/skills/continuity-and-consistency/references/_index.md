# continuity-and-consistency — reference index

The deep reference files for the `continuity-and-consistency` skill. **These are authored in a later pass**; this index is the plan. The parent `SKILL.md` holds the one-line framework catalogue, the how-to-use method, and the house disciplines — read it first. Each file below expands its `SKILL.md` section: for each framework, the deep treatment adds *what it is*, *the real-world provenance / key source*, *the Limit or contested edge*, *a vivid exemplar*, and *how to use it at gate-time* (name → route → compute-or-judge → flag/correct). Every file stays **framework-neutral** (rival schemes side by side) and serves the one non-negotiable: **the floor must hold — no contradiction enters canon; catches are flagged, never fixed, and corrected forward, never mutated.**

Files are ordered to the critic's working path (what canon is → what can break it → how each break is decided → how the whole scene is checked → what to do with a catch → the catalogue → the house method), with the load-bearing house-method file last. Each digests its `docs/` canon and points back to it (`design.md`, `world-state-ledger.md`, `consolidation-loop.md`, `knowledge-model.md`, `narration.md`, `scene-assembly.md`, `arc-engine.md`, `relationships.md`, `probe-plan.md`); the doc stays the source of truth.

Each reference file follows the repo's reference-entry format (`docs/agent-toolboxes.md`): **When to load · Canon · the menu (framework-neutral) · the repo default (swappable) · in-practice examples · limits.**

## A. What canon IS

### 1. `canon-and-continuity.md` — the object of the check
**Feeds:** the critic's premise — what "canon" is here, and how it is tracked when it exceeds the context window.
**Covers:** canon (fiction) and its Sherlockian/biblical origins; the story/series/show bible (the writers'-room continuity guide) as the analog of the World Bible; the world-state ledger as *living* canon (bible = rules, ledger = history); canon vs fanon vs headcanon vs Word of God (degrees of authority); retcon (controlled vs accidental); canon discontinuity / negative continuity / soft-vs-hard canon; the sliding timescale / floating timeline (managed inconsistency); continuity databases & fan wikis (Memory Alpha, Wookieepedia, the "continuity cop"); continuity (surface agreement) vs consistency (rule/logic agreement); groundedness as a retrieval problem (`design.md`).
**Spine:** establishes what the gate defends and why it is hard: at book scale the bible exceeds context, so consistency is a retrieval-then-check, not an automatic property. Names the project default — the append-only ledger + folded snapshot *is* the canon of record — and flags it swappable (a fork could keep canon in a wiki, a graph, a doc). The subtlest failure lives here: a missed retrieval reads as a false pass, so "what canon is" is inseparable from "how it is fetched."

## B. The taxonomy

### 2. `contradiction-taxonomy.md` — the master map of what can break
**Feeds:** every gating decision — naming a suspected break and routing it to the engine or to judgment.
**Covers:** the event-indexing model (Zwaan, Langston & Graesser 1995 — the five reader-tracked dimensions: time, space, protagonist/entity, causation, intentionality); the de Marneffe, Rafferty & Manning (2008) contradiction typology (antonymy, negation, numeric, factive/modal, structural, lexical, world-knowledge; the easy/hard split); the definition of contradiction ("cannot both hold of the same situation") and the event-coreference prerequisite; the house taxonomy (fact · timeline · spatial · character/knowledge · causal · tonal · voice · rule) mapped onto both sources with a decider (engine vs critic) per class; each class defined with an exemplar; the false-positive discipline (surprise, arc, and the recorded lie are not contradictions); severity & blockingness (the depth rule for error triage).
**Spine:** the toolbox's center of gravity — the map every other reference plugs into. Grounds the working classes in cognition (Zwaan: the reader *feels* a break on exactly these axes) and in NLP (de Marneffe: the linguistic anatomy of a fact clash), then names who decides each. Carries the discipline that keeps the gate precise: it screens beat-*vs-canon*, never the honest divergence *within* a beat. This is the project's default taxonomy, flagged **swappable**: a fork re-cuts the classes here and the routing follows.

## C. The reasoning engines

### 3. `timeline-reasoning.md` — settling an ordering or duration
**Feeds:** any temporal, anachronism, or effect-before-cause check.
**Covers:** Allen's interval algebra (the 13 relations); point algebra (Vilain & Kautz); temporal constraint networks (TCSP/STP; Dechter, Meiri & Pearl); composition tables & path-consistency; tractable subalgebras & the NP-completeness of full Allen (ORD-Horn); TimeML/TLINK & timeline extraction; Reichenbach's speech/event/reference time; the ledger clock & as-of-T slicing (`world-state-ledger.md`, `knowledge-model.md`); duration & travel-time feasibility (the depth rule for time); effect-before-cause / causal-temporal coupling.
**Spine:** the engine-side calculus for the timeline class — the deterministic "compute, don't argue" half of the gate for order and duration. Grounds the project's ledger clock in the formal machinery that decides "could the character be here now?" and "does this event precede its own cause?" Carries the depth rule: resolve travel-time or exact ordering only at a hinge that turns on it; class-default elsewhere.

### 4. `spatial-reasoning.md` — settling a geometry, reachability, or staging break
**Feeds:** any spatial, reachability, or screen-direction check.
**Covers:** Region Connection Calculus (RCC-8 — the 8 topological relations); cardinal-direction calculus & the rectangle algebra; qualitative spatial reasoning & path-consistency; spatial situation models (Bower & Morrow 1990; Zwaan & Radvansky 1998 — the reader's tracked mental map); the 180-degree rule / axis of action & screen direction (script supervision); blocking & staging continuity + the reach check; reachability & line-of-sight (`scene-assembly.md` — the PerceptSet is already spatial); mental maps & cognitive-map distortion; map/floorplan invariance & the depth rule for space.
**Spine:** the engine-side calculus for the spatial class. Ties the project's existing spatial machinery (line-of-sight, earshot, the PerceptSet) to the formal calculi that decide co-location, containment, and reachability, and imports the film-craft discipline (screen direction, the axis of action) as the prose analog of who-faces-whom staying fixed. The reader holds a spatial map (Bower & Morrow), which is *why* a geometry break is felt — and why it is worth computing.

### 5. `character-and-knowledge-consistency.md` — is the act in character and within what the character can know?
**Feeds:** any character, motivation, or knowledge check.
**Covers:** persona consistency & the persona profile (PersonaChat); Dialogue NLI (Welleck et al. 2019) & DECODE (E/N/C ratio; contradiction across a history); characterization & the consistent character (Aristotle's *Poetics*; McKee); Out-of-Character / character derailment; Flanderization (slow drift); trait/value drift vs earned arc (`arc-engine.md`); the vault / knowledge-consistency check (`knowledge-model.md` — computed vault-membership); dramatic irony vs the knowledge break (the same asymmetry, two verdicts); motivation consistency & goal-tracking (Zwaan's intentionality); capability & affordance (the recorder's check re-run); relationship-state consistency (`relationships.md`).
**Spine:** the character class, split cleanly along the hybrid seam — the **knowledge/capability** half is *computed* (is this fact in the vault? could the actor do it?), the **out-of-character/motivation** half is *judged*. Holds the two sharpest disciplines: acting on unlearned knowledge is the crispest continuity break (and it is an engine query, not a debate), while distinguishing an out-of-character violation from an earned arc is the critic's own reading and must never flag growth as drift.

### 6. `voice-consistency.md` — do the voices stay distinct and true?
**Feeds:** any voice or diction check — the LLM half of the gate.
**Covers:** stylometry & the idiolect; Mosteller & Wallace (1964) / the Federalist Papers; Burrows's Delta (2002) over most-frequent-word z-scores; function words as the topic-independent signal; authorship verification vs attribution (the critic's question is verification); register/diction & idiolect/sociolect/dialect; distinct-voice detection as the LLM half (`design.md`, `narration.md`); the voice-collapse failure mode (regression to one house style); character-n-gram/burstiness/richness features; verbal tics/catchphrases/lexical signatures; voice as bounded by POV.
**Spine:** the voice class — design.md's explicit "distinct-voice / tone is LLM." Presents the quantitative stylometric tradition (function words, Delta) as the *evidence base* a judgment can lean on, while keeping the verdict interpretive: no script rules that two minds have collapsed. Names the specific long-form pathology the critic exists to catch — the LLM's pull to make every character sound the same — and distinguishes a true diction break from a POV-boundary leak.

## D. The check

### 7. `checking-against-canon.md` — validating a whole beat against bible + ledger
**Feeds:** the end-to-end scene-vs-canon check and its hybrid, retrieval-bounded shape.
**Covers:** the check as knowledge-base validation (add the beat's claims → does the KB stay consistent?); integrity constraints & closed-world validation (SHACL); ontology/description-logic consistency checking (Pellet, HermiT; tableaux); open-world (bible laws) vs closed-world (ledger state) and why mixing them silently breaks the check; NLI/textual entailment (entail/neutral/contradict; DeBERTa); claim decomposition & fact verification (FEVER — supported/refuted/NEI); groundedness/faithfulness & attribution (AIS); retrieval of the relevant slice (groundedness is a retrieval problem); truth-maintenance systems (Doyle 1979; de Kleer's ATMS); the hybrid split at the check; self-consistency & cross-checking (SelfCheckGPT; cross-extractor agreement); the one-way arrow at the check (prose checked read-only against the biography).
**Spine:** the method file for section D — how the gate actually runs over a whole beat, wiring the taxonomy's classes to concrete detectors. Holds the two engineering truths that make the check honest: the **open-world/closed-world seam** (infer over the bible, enforce over the ledger) and the **retrieval bound** (the check is only as good as the slice fetched — a missed retrieval is a false pass). The project default is the hybrid engine/LLM split; a fork could go all-LLM (an NLI judge over everything) or all-symbolic (a full DL reasoner) — both are held as legitimate, costed alternatives.

## E. The policy

### 8. `flag-vs-correct.md` — what to do with a catch
**Feeds:** every remedy decision, and the correction protocol for a bad record already on the log.
**Covers:** the non-author stance (checker ≠ writer); event sourcing & the append-only floor (`world-state-ledger.md`); compensating events & the Saga pattern (forward-only reversal; `consolidation-loop.md` open-Q #3); retcon as a controlled operation vs an accident; the remedy ladder (reject+regenerate → director-revise → compensating-event → escalate); never-silent-never-mutate (a correction is visible and non-destructive); flag-with-provenance & a remedy *class* (not a patched line); selective prediction & abstention; confidence, calibration & the escalation threshold (`consolidation-loop.md` open-Q #2); measured-not-trusted & the coherence probe (`probe-plan.md`); the compounding-error asymmetry (a false pass is unforgivable, a false flag merely costs a regeneration).
**Spine:** the policy that defines the critic as a *gate*, not an editor. Grounds "never silent mutation" not in etiquette but in structure — the log is append-only, so a compensating event is the *only* correction shape available — and names the remedy ladder so each catch is handed to whoever owns the fix. This is the project's default correction protocol, flagged **swappable** in mechanism (how a compensating event is authored) but not in principle (forward-only, visible, non-destructive). Names consolidation-loop open questions #2 (confidence + threshold) and #3 (compensating-event correction) and holds them open.

## F. The catalogue and the house method

### 9. `classic-continuity-errors.md` — the field guide of known long-form failures
**Feeds:** pattern-matching a suspected break against a named, real-world exemplar — and knowing where to look first.
**Covers:** the movable/floating fact (Watson's wound shoulder→leg; the "Great Game" rationalization the critic must *not* perform); name & relation drift (Watson's wife "James" not "John"); the Continuity Snarl; the Plot Hole; negative continuity / the reset button; Mood Whiplash; Flanderization; the dropped thread / Chekhov's gun unfired (and its inverse, payoff-without-setup); off-screen teleportation & the resurrected object; the idiot ball & the out-of-character lapse under plot pressure; conservation errors (the healing wound; vanishing resources); anachronism & era leakage; why these compound in long form (the LLM long-story consistency-bug finding — errors cluster in fact/temporal dimensions, mid-narrative, in high-entropy spans).
**Spine:** the concrete, exemplar-rich companion to the abstract taxonomy — each classic error tagged to its taxonomy class and its decider, so the critic can recognize a break by its family resemblance. Doubles as a triage heat-map: the empirical long-form finding tells the gate *where to look first* (fact and time, around the middle, in the loose spans). Every exemplar is real and cited; the file is a well of cautionary instances, not a rulebook.

### 10. `the-critic-gate.md` — the gate's whole philosophy
**Feeds:** every gating decision — the load-bearing reference, the spine, not one file among ten.
**Covers:** the non-author gate (`design.md` layer 6); the no-contradiction floor at write time (`world-state-ledger.md`); the hybrid engine/LLM split (compute what has a value, judge only what doesn't); the one-way arrow (stream = ground truth; prose checked read-only against the biography; `design.md`); flag-never-fix & correct-forward-never-mutate (→ *flag-vs-correct*); the false-positive discipline (faithful refusal, recorded lie, earned growth are not contradictions; `recording-model.md`); measured-not-trusted (provenance + calibrated confidence + escalation; the coherence probe, `probe-plan.md`); the compounding asymmetry (false pass ≫ false flag); the critic as the recorder's backstop (`consolidation-loop.md`); groundedness is a retrieval problem (the silent-false-pass failure).
**Spine:** the meta-file that ties every framework above back to the project's layer-6 gate and the design.md one-way arrow — where the critic's whole identity is stated in full: a non-author check enforcing the no-contradiction floor, hybrid by construction, correcting forward and never in place, precise enough never to flag autonomy or an honest lie, and honest enough to escalate its own doubt. Where the well's stance (a neutral, forkable draw-from) meets the one non-negotiable: the floor holds, because a false pass compounds through every later beat and into the book.

## Authoring notes for the later pass
- **One file per section of `SKILL.md`, same order, same names** — the index and the catalogue stay in lockstep.
- **Per framework, five fields:** what it is · real-world provenance + key source (accurate, cited, never invented) · its Limit / contested edge · a vivid exemplar (a real case where possible) · how to use it at gate-time (name → route → compute-or-judge → flag/correct).
- **Neutrality is mandatory:** where schemes rival (symbolic reasoner vs NLI judge; interval algebra vs point algebra; function-word stylometry vs neural authorship; closed-world integrity constraints vs open-world DL), present both and name the tension; the gate chooses, not the file. The one non-negotiable that overrides neutrality is the floor: every file serves it.
- **Compute vs judge — keep the seam visible in the files too:** mark every check as engine (has a value → computed) or critic (interpretive → judged); an example that "argues" a timeline it could compute, or "computes" a voice it should judge, has crossed the seam.
- **Flag, never fix — in the examples too:** worked cases end at a *finding with a remedy class*, never a rewritten line; a correction to an appended record is shown as a *compensating event*, never a mutation. If an example needs the fix applied, name it as the sim's / director's / recorder's to do.
- **Refuse the false positive — in the examples too:** include cleared non-contradictions (a faithful refusal, a recorded lie, an earned arc) so the files teach precision, not just detection.
- **Ground everything:** no invented calculus, category, or attribution without its source; verify names, dates, and claims (Allen's 13 relations, RCC-8's 8 relations, de Marneffe's 7 types, Zwaan's 5 dimensions, Burrows's Delta, Mosteller & Wallace, the FEVER labels, the reasoner names) before writing.
- **Cross-link to `docs/`:** each file points back to its canon — `design.md` (layer-6 critic + one-way arrow + compute/generate split), `world-state-ledger.md` (the immutable log + the continuity gate), `consolidation-loop.md` (the consistency critic + compensating events + measured-not-trusted + the open questions), `knowledge-model.md` (the vault), `narration.md` (distinct-voice/tone), `scene-assembly.md` (line-of-sight + PerceptSet), `arc-engine.md` (earned change), `relationships.md` (relationship state), `probe-plan.md` (the coherence probe) — and to the sibling references it seams with (taxonomy ↔ every engine; checking-against-canon ↔ flag-vs-correct; the-critic-gate ↔ all). The `docs/` file stays canon; the reference is its work-time face.
