# event-semantics — reference index

The deep reference files for the `event-semantics` skill. **These are authored in a later pass**; this index is the plan. The parent `SKILL.md` holds the one-line framework catalogue, the how-to-use method, and the house disciplines — read it first. Each file below expands its `SKILL.md` section: for each framework, the deep treatment adds *what it is*, *the real-world provenance / key source*, *the Limit or contested edge*, *a vivid exemplar*, and *how to use it at record-time* (validate → complete → type → ground). Every file stays **framework-neutral** (rival schemes held side by side) and serves the keystone discipline: **the record must be true, auditable, and lossless — facts, never deltas; the stream, never the narration.**

Files are ordered to the recorder's working path (representation → roles → speech/narrative kinds → the vocabulary → extraction → the contract → trust → the house method), with the load-bearing house-method file last. Each digests its `docs/` canon and points back to it (`consolidation-loop.md`, `recording-model.md`, `design.md`, `state-engine.md`, `world-state-ledger.md`, `probe-plan.md`); the doc stays the source of truth.

Each reference file follows the repo's reference-entry format (`docs/agent-toolboxes.md`): **When to load · Canon · the menu (framework-neutral) · the repo default (swappable) · in-practice examples · limits.**

### 1. `event-representation.md` — the anatomy of an event
**Feeds:** the consolidation seam (design.md LLM call 3) — deciding what counts as one event and how it sits in time and cause.
**Covers:** Davidsonian & neo-Davidsonian event semantics (event variables + role predicates); Vendler's aspectual classes / Aktionsart; telicity & boundedness; the event-vs-state(condition) distinction; Reichenbach's speech/event/reference time; situation & event calculus (McCarthy & Hayes; Kowalski & Sergot); fluents vs events; TimeML (EVENT/TIMEX3/SIGNAL/TLINK); Allen's 13 interval relations; causal ordering (ENABLE/CAUSE/PREVENT); event coreference; the five Ws → the ledger's `{what·who·when·where·consequence}`.
**Spine:** the recorder's first cut — *is this one bounded event, an ongoing process, or a standing condition?* Grounds the event-vs-condition rule (`state-engine.md`: verbs fire once → appraisal; conditions persist → catalog) in aspectual theory, and gives the temporal/causal scaffolding a coherent biography needs. Carries the depth rule: bound and order only to the grain the book levers on.

### 2. `semantic-roles-and-frames.md` — the slots an event fills
**Feeds:** the five-slot tag — assigning `target`/`instrument`/participants and their roles.
**Covers:** thematic (theta) roles (agent/patient/experiencer/instrument/goal/source/beneficiary/recipient/location/stimulus); Fillmore's case grammar; Dowty's proto-Agent/proto-Patient entailment clusters; frame semantics & FrameNet (frames, frame elements core/peripheral, lexical units, valence); PropBank (Arg0–Arg5, ArgM); VerbNet & Levin's verb classes + diathesis alternations; Semantic Role Labeling; Abstract Meaning Representation; Generative Lexicon & qualia; the project's `{act, target, instrument, intent, stance}` as a compressed frame.
**Spine:** how a raw act resolves into *who played what part* — so `target` and `instrument` are assigned by principle (proto-role entailments settle the edge cases), and the five-slot tag is understood as a deliberate compression of a full frame (what it keeps: act + core elements + self-reported interior; what it drops, and the cost). Threads diathesis alternations: the same event surfaces many ways in prose — the tag must be invariant under them.

### 3. `speech-acts-and-dialogue.md` — recording what was said as an act
**Feeds:** every dialogue turn — promises, threats, reveals, and the lie.
**Covers:** Austin's locutionary/illocutionary/perlocutionary split & the illocution-not-perlocution wall; performatives vs constatives & felicity conditions; Searle's five illocutionary classes (with illocutionary point / direction of fit / psychological state); illocutionary force & IFIDs; Grice's cooperative principle, maxims & implicature (what's meant beyond what's said; flouting); indirect speech acts; dialogue-act taxonomies (DAMSL/SWBD-DAMSL, DIT++, ISO 24617-2/DiAML); conversation analysis (adjacency pairs, turn-taking, repair); Brown & Levinson politeness / face-threatening acts; the recorded lie as `thought ≠ action`.
**Spine:** dialogue is action — a line is typed by the *act it performs*, not its surface form, and the recorder logs the **illocution** (A threatened, A promised, A revealed) while leaving the **perlocution** (was B cowed, convinced, hurt) to B's own stream and the engine. The exact speech-act mirror of the character-simulator's "report intent, never effect." Carries the deception protocol (`recording-model.md`): the lie is preserved as the thought/action gap, never collapsed.

### 4. `narrative-event-models.md` — how events chain into a biography
**Feeds:** the biography substrate — relating events across a scene; checking the log reads as coherent history.
**Covers:** story grammars (Rumelhart; Mandler & Johnson; Thorndyke — setting + episode: initiating event/reaction/goal/attempt/outcome/resolution; AND/THEN/CAUSE links); Propp's 31 functions & 7 dramatis-personae; Schank & Abelson scripts/plans/goals/themes; Conceptual Dependency & the 11 primitive ACTs; Lehnert's plot units (affect states + causal/cross-character links); Chambers–Jurafsky narrative event chains & schemas + the narrative cloze; Story Intention Graphs (Elson/Scheherazade/DramaBank); fabula vs syuzhet & story vs discourse (Formalists; Chatman; Genette); Barthes' cardinal functions (nuclei) vs catalysers.
**Spine:** the recorder builds the **fabula** — events as they happened, the biography's ground truth — and the narrator renders the **syuzhet**; this file states the one-way arrow in narratology's own vocabulary and gives the coherence-structure a chronicle must satisfy. Doubles as the closed-inventory lineage (Propp, CD primitives, Lehnert) that motivates a bounded event vocabulary.

### 5. `the-appraisal-event-vocabulary.md` — the project's bounded schema and its lineage
**Feeds:** picking the `act` — and checking whether a turn needs a type the schema lacks.
**Covers:** the house vocabulary (harm/aid/betray/reveal/acquire-knowledge/bond/threaten/relationship-act + speak/move/give/take/conceal/submit/defy/observe); the five-slot tag; the three payoffs of a closed set (validatable / appraisable / stable contract); the act→appraisal-dimension→primary mapping (goal-congruence, agency, certainty, control, norm-violation → SEEKING/FEAR/RAGE/CARE/PANIC-GRIEF/LUST/PLAY); the event-vs-condition boundary; the closed-inventory lineage (Schank, Propp, Lehnert, FrameNet hierarchies); schema gaps & the extension protocol; vocabulary granularity (the depth rule for acts).
**Spine:** the toolbox's center of gravity — *this* is the schema the recorder picks from, grounded in the tradition of reducing action to a small typed set and wired to the appraisal engine it must feed without computing. This is the project's default, flagged **swappable**: a fork replaces this one file to change the event ontology, and the recorder, router, and every other reference are untouched. Names Open Question #1 from `consolidation-loop.md` (the minimal complete event-type set) and holds it as an open, forkable choice.

### 6. `event-extraction.md` — getting events out of the stream
**Feeds:** the mechanical pipeline — trigger + argument extraction for what the actor didn't self-report.
**Covers:** trigger + argument-role extraction; MUC template filling; the ACE 2005 ontology (8 types/33 subtypes/22 roles) & ERE/RED/MAVEN/DocEE successors; OpenIE triples (the schema-free pole, and why the project declines it); semantic parsing; NER/coreference/relation extraction as prerequisites; cross-turn/cross-document event coreference; temporal & causal relation extraction (CATENA, Causal-TimeBank); LLM structured extraction (function-calling, constrained decoding, JSON-schema); self-report vs mining; evaluation (trigger/argument P/R/F1).
**Spine:** the how-to of extraction *and* the argument for the project's inversion of it — the actor self-reports (validate, cheap, high-fidelity) rather than an observer mining prose (guess, expensive, lossy). Presents the field's ontologies as worked models for the house vocabulary, and treats LLM structured output as the modern method that still *requires* validation because a model can hallucinate a referent. The interpreter→validator posture stated as method.

### 7. `typed-schemas-and-self-report.md` — the contract and who fills it
**Feeds:** validating a tag; reasoning about schema design and the recording split.
**Covers:** closed vs open vocabularies (the trade); controlled vocabularies/ontologies/taxonomies (SKOS); JSON Schema & typed structured output (enums, required slots, well-formedness); design by contract (schema as sim↔engine interface); the actor-records principle (self-report reliability); nobody-records-another's-mind (the POV wall, cross-char via perception); the three validation checks (schema-conformance / containment / capability); referential grounding (anti-hallucination); event-schema induction (learned vs authored schemas).
**Spine:** the engineering of the contract — *why* schema-is-primary (design-by-contract), *who* fills each slot (Principles 1–2 of `consolidation-loop.md`: doer self-reports, no one records another's interior), and the mechanical gate every tag passes before it can enter state. This is where the recorder's "validator, not interpreter" identity is grounded in reliability theory and interface design.

### 8. `provenance-confidence-and-verification.md` — making the record auditable and measured
**Feeds:** scoring a record, flagging a doubt, standing up the tests (Principle 4 + the measurement regime + the correction protocol).
**Covers:** provenance (W3C PROV: entity/activity/agent; wasGeneratedBy/wasDerivedFrom/wasAttributedTo/used) & data lineage / source spans; confidence scoring & calibration (verbalized confidence, logprobs, ECE); selective prediction & abstention; escalation thresholds; inter-annotator agreement (Cohen's κ, Fleiss' κ, Krippendorff's α) & reliability thresholds; cross-extractor ensembles; ground-truth replay (unit test); round-trip/reconstruction (information-preservation / lossy check); the coherence probe (integration test, `probe-plan.md`); faithfulness & attribution (AIS, groundedness, hallucination); event sourcing & compensating events (append-only, forward-only correction); the read-only critic backstop.
**Spine:** "everything depends on accuracy" → therefore accuracy must be **verifiable**, not assumed. This file is the measurement regime and the trust machinery: every record carries provenance + an honest confidence, ambiguity is flagged and escalated (never silently committed), disagreement across extractors is a signal, and the log is corrected forward by compensating events, never mutated. Names Open Questions #2 (confidence + escalation threshold) and #3 (compensating-event correction) from `consolidation-loop.md`.

### 9. `the-prose-event-contract.md` — the seam between prose and structured events
**Feeds:** every consolidation decision — the load-bearing reference, the spine, not one file among nine.
**Covers:** the one-way arrow (`stream → events → state` in-sim vs `biography → narration → prose` terminal); read-the-stream-never-the-narration (the anti-forcing wall); extract-events-never-deltas (the compute/generate seam); illocution-not-perlocution; validate-don't-mine (Principle 1); nobody-records-another's-mind (Principle 2); the bounded typed vocabulary (Principle 3); measured-not-trusted (Principle 4); lossy-vs-lossless (the round-trip standing check); the compounding-error / keystone argument.
**Spine:** the meta-file that ties every framework above back to the project's four consolidation principles and the design.md one-way arrow — where the recorder's whole philosophy is stated in full: the record is the biography's ground truth, so it must be true by construction; facts not deltas, the stream not the telling, the doer's self-report validated not mined, no mind read but one's own, every record grounded and confidence-scored. Where the well's stance (a neutral, forkable draw-from, never a prescribed pipeline) meets the one non-negotiable: accuracy, because it compounds.

## Authoring notes for the later pass
- **One file per section of `SKILL.md`, same order, same names** — the index and the catalogue stay in lockstep.
- **Per framework, five fields:** what it is · real-world provenance + key source (accurate, cited, never invented) · its Limit / contested edge · a vivid exemplar · how to use it at record-time (validate → complete → type → ground).
- **Neutrality is mandatory:** where schemes rival (closed vs open vocabulary, thematic-role lists vs proto-roles, script-based vs learned narrative models), present both and name the tension; the record chooses, not the file. The one non-negotiable that overrides neutrality is accuracy — every file serves it.
- **Facts, never deltas — in the files too:** examples show events extracted and *stopped at the wall*; never model an emotion or a number as if the recorder produced it. If an example needs a consequence, name it as the *engine's* to compute.
- **Ground everything:** no invented ontology, role name, or attribution without its source; verify names, dates, and claims (FrameNet counts, ACE type lists, Searle's five classes, Allen's 13 relations, the κ/α thresholds) before writing.
- **Cross-link to `docs/`:** each file points back to its canon — `consolidation-loop.md` (the four principles + open questions), `recording-model.md` (two streams + the lie), `design.md` (LLM call 3 + the one-way arrow + the compute/generate split), `state-engine.md` (appraisal + event-vs-condition), `world-state-ledger.md` (the event log + fold), `probe-plan.md` (the coherence probe) — and to the shared appraisal dimensions and Panksepp primaries.
